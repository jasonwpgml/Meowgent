# 단축키 힌트 조사 (2026-10-21)

> **구현 상태 (2026-10-21):** 아래 §5의 1~3번을 만들었다. 4번(⌘ 길게 누르기 표)·5번(주간 정리)은 아직. 코드: `collector/Sources/ActLog/ShortcutRules.swift`(규칙·횟수, 테스트 있음) · `ShortcutCoach.swift`(메뉴 읽기·저장·메뉴) · `PetController.keyHint`(키캡).

마우스로 한 일에 단축키가 있으면 고양이가 알려 주는 기능. 만들 수 있는지, 내 기록에서 무엇이 걸리는지, 어떻게 알려야 효과가 있는지 조사했다.
결론: **만들 수 있다.** 다만 메뉴 클릭만 보는 흔한 방식으로는 내 기록의 거의 아무것도 못 잡는다. 창 단추·브라우저·앱 전환을 따로 규칙으로 잡아야 한다.

## 1. 내 기록 분석 (ActLog, 10/14~10/20, 클릭 14,724번)

| Dock 앱 아이콘 클릭 | 103 | ⌘Tab, ⌘Space |
| 빨간 닫기 단추 | 69 | ⌘W |

| Chrome 새 탭 | 43 | ⌘T |
| Finder 뒤로 | 21 | ⌘[ |
| Chrome 주소창 클릭 | 19 | ⌘L |

합계 약 540번, 하루 약 77번. Lane et al.(2005) 측정값(아이콘보다 0.66초, 메뉴보다 1.48초 빠름)으로 치면 **하루 1분 안팎**이다.
시간 자체보다는 손이 키보드를 떠나지 않는 것, 흐름이 덜 끊기는 것이 이득이다. 기대치를 크게 잡지 않는다.

### 단축키가 있지만 더 빠르다고 할 수 없는 것

- **Claude 앱 사이드바에서 세션 클릭: 약 690번 (하루 100번, 가장 많음).** Claude 앱에는 ⇧⌘K(세션 검색), ⇧⌘[ / ⇧⌘](이전·다음 세션)가 있다.
  하지만 화면에 보이는 세션 하나를 고르는 건 마우스가 더 빠를 수 있다. 바로 옆 세션으로 갈 때나 목록에 안 보이는 세션을 찾을 때만 권한다.
- 메뉴 막대 메뉴를 직접 누른 건 7일에 128번뿐이고, 대부분 메뉴 막대 앱(CodexBar 등)이다. → **메뉴만 보는 방식은 거의 안 걸린다.**

### 못 보는 것

- 클릭의 66%는 이름 없는 요소(빈 영역, 웹 내용)다. ChatGPT 앱은 83%. 글 선택·입력창 포커스가 대부분이라 단축키와 상관없는 경우가 많지만, Electron 앱 안의 단추는 이름을 못 읽는 경우도 있다.
- **지금은 내가 단축키를 쓰는지 모른다.** ActLog는 키 횟수와 Enter·⌘V만 본다. 그래서 "이미 ⌘W를 잘 쓰는데 가끔 단추를 누른 것"과 "⌘W를 모르는 것"을 구분 못 한다.

### 잘못 맞추면 위험하다 (실제 사례)

단추 이름과 메뉴 이름을 느슨하게(부분 일치) 맞춰 보니 이런 오답이 나왔다.

| 누른 것 | 느슨하게 맞춘 메뉴 | 문제 |
|---|---|---|
| Claude 대화상자 "닫기" (16번) | 세션 닫기 ⌘W | 따라 하면 **세션이 닫힌다** |
| Claude "이미지 확대: …" | 확대 ⌘+ | 화면 글자가 커진다 |
| Claude "기타" | 기타 가리기 ⌥⌘H | 다른 앱이 숨겨진다 |

→ **이름이 정확히 같을 때와 손으로 확인한 규칙만 쓴다. 확실하지 않으면 말하지 않는다.**

## 2. 기술적으로 되는가 (이 맥에서 확인)

- 앱 메뉴의 단축키는 손쉬운 사용(AX)으로 읽힌다: `AXMenuItemCmdChar`, `AXMenuItemCmdModifiers`(⌘는 기본, 비트 0 ⇧ · 1 ⌥ · 2 ⌃ · 3 ⌘ 없음), 특수 키는 `AXMenuItemCmdVirtualKey`/`Glyph`.
  실측: Claude 68개 0.06초, ChatGPT 57개 0.12초, Chrome 84개 0.25초, Finder 117개 0.14초. 앱이 앞으로 올 때 한 번 읽어 두면 된다.
- 창 단추는 subrole로 바로 안다: `AXCloseButton` · `AXMinimizeButton` · `AXFullScreenButton`. 대화상자는 `AXDefaultButton`(↩) · `AXCancelButton`(⎋).
- 탭은 부모가 `AXTabGroup`인지로 안다. Dock 아이콘은 `AXApplicationDockItem`.
- 시스템 단축키(Spotlight, 데스크톱 이동 등)는 `com.apple.symbolichotkeys`에서 읽는다. 기본값은 파일에 없을 수 있어 기본표를 함께 둔다.
- 내가 바꾼 앱 단축키(`NSUserKeyEquivalents`)는 AppKit이 메뉴에 반영하므로 AX 값에 이미 들어 있을 것이다 (추정, 확인 필요).
- 웹페이지 단추의 단축키(`aria-keyshortcuts` → `AXKeyShortcutsValue`)는 Chrome·Safari가 내보내지만, 쓰는 사이트가 드물다. Gmail·Notion·Slack 같은 건 사이트별 표가 필요하다.
- Chrome·Electron 앱의 웹 내용 AX를 강제로 켜면 느려지고 화면 읽기 모드처럼 동작할 수 있다 (`AXManualAccessibility`, Shortcat 변경 기록). → 켜지 않는다.
- 메뉴 항목은 클릭하자마자 사라지므로, 클릭한 요소는 이벤트 탭에서 바로 잡아야 한다 (Shortcut Coach 방식, AX 요청 제한 0.15초).

## 5. 설계

1. **단축키 쓰는지 알기 (먼저 해야 함).** 이벤트 탭에서 ⌘ 또는 ⌃가 눌린 키만 `(키 위치, 수정 키)`로 보고, 메모리에서 메뉴 색인과 맞춰 **명령별 횟수만** 저장한다. 글자·일반 타자는 저장하지 않는다.
   ActLog README의 "무슨 키를 눌렀는지 보지 않음"을 바꾸는 일이라 사용자 승인이 필요하다.
2. **단축키 색인.** 앱이 앞으로 오면 메뉴를 읽어 캐시(앱별 최대 0.5초, 노드 3000개). 여기에 창 단추, 대화상자, Dock·Mission Control(시스템 단축키), 브라우저 고정표를 더한다.
3. **맞추기.** 메뉴 항목 클릭 = 그 항목의 단축키. 단추 = 같은 앱 메뉴와 이름이 **정확히** 같을 때만. 나머지는 손으로 확인한 규칙만. 애매하면 말하지 않는다.
   앞으로 Clef/gemma가 밤에 "이 단추 ↔ 이 메뉴" 후보를 찾아 아침 승인 목록에 올리는 방식(RESEARCH.md §4)으로 늘릴 수 있다.
4. **알리는 법.** 클릭 직후 고양이 옆에 작은 키캡(`⌘[`)이 2~3초 떴다 사라진다. 누를 필요 없음, 포커스 안 뺏음, 깜빡임 없음.
   - 같은 동작을 같은 날 3번째 마우스로 할 때 처음 알린다. 한 동작은 하루 한 번.
   - 그 단축키를 키보드로 3번 쓰면 그 동작은 더 말하지 않는다.
   - 회의·화면 공유·집중 모드·타자 중엔 안 띄운다. 말풍선 예산(20분 1번)과는 따로 두되, 하루 10번 이하.
   - 힌트별 "이건 그만", 전체 끄기.
5. **당겨 보기.** ⌘를 1초 누르고 있으면 고양이가 지금 앱의 단축키를 **내가 마우스로 자주 하는 순서대로** 보여 준다. ⌘ 떼거나 다른 키 누르면 바로 닫힘. 보안 입력 중엔 안 띄움.
6. **주간 정리.** "이번 주 놓친 단축키 5개, 아낄 수 있던 시간", "새로 익힌 것".

## 6. 만든 것 (1~3번)

| 규칙 | 단축키 | 조건 |
|---|---|---|
| 메뉴 항목 클릭 (메뉴 막대·우클릭 메뉴) | 그 항목에 적힌 것 | ⌘나 ⌃가 들어간 것만 |
| 빨강·노랑·초록 창 단추 | 그 앱 메뉴의 "창 닫기"·"최소화"·"전체 화면 시작" | 메뉴에 없으면 말 안 함. Claude는 ⇧⌘W |
| Dock 아이콘 | 켜진 앱 ⌘⇥, 꺼진 앱 Spotlight 단축키 | Spotlight 단축키를 끄면 말 안 함 |
| Mission Control 데스크톱 줄 ("데스크탑 2", "A 및 B") | ⌃← ⌃→ | 시스템 설정에서 꺼져 있으면 말 안 함. 앱 이름 하나짜리 썸네일은 말 안 함 |
| 브라우저 주소창 · 탭 | ⌘L · ⌃⇥ / ⌘1~9 | 웹 페이지 안쪽 입력칸·탭은 제외 |
| 단추 이름 = 같은 앱 메뉴 이름 | 그 메뉴 항목의 것 | 정확히 같을 때만. "닫기·복사·확인" 같은 모호한 이름 제외. 브라우저는 웹 페이지 바깥만 |

- Claude 사이드바 세션 클릭은 넣지 않았다: 보이는 세션 고르기는 마우스가 더 빠를 수 있다.
- 대화상자 ↩·⎋는 넣지 않았다: ⌘·⌃ 없는 키라 "익혔는지"를 셀 수 없다.
- 보여 주기: 같은 날 3번째 마우스 사용 때, 한 동작은 하루 한 번, 하루 10개까지, 힌트 사이 20초 이상. 그 단축키를 키보드로 3번 쓰면 더 말하지 않는다. 숨김·전체 화면·일시정지·말풍선 중엔 안 띄운다.
- 키캡은 머리 위에 3초 떴다가 0.4초 동안 흐려진다. 클릭 통과.
- 고양이 우클릭 메뉴 › ⌨️ 단축키 힌트: 전체 켜고 끄기, 방금 힌트 그만 보기, 최근 7일 마우스로 한 것(눌러서 힌트별 켜고 끄기).
- 점검: `printf 'key:⌘[ 뒤로' > ~/Library/Application\ Support/ActLog/pet_cmd` 하면 키캡이 바로 뜬다.

지난 7일 기록을 새 규칙에 다시 돌린 결과 (단축키를 한 번도 안 썼다고 가정): 하루 힌트 1~10개. 가장 많이 걸린 것은 Dock ⌘⇥(78), Mission Control ⌃←→(64), Chrome ⌘[(48)·⌘T(43), Finder ⌘[(21)·⌘W(19), Chrome ⌘L(19).
